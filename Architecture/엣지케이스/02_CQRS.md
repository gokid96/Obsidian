# CQRS 엣지케이스

## 1. "방금 한 행동이 안 보임" — Read 지연

| 항목 | 내용 |
|------|------|
| **문제** | Write 후 Read 모델에 반영되기까지 시간 소요 |
| **왜 발생** | Eventual Consistency 특성상 동기화 지연 |
| **해결** | Write-through 캐시, 클라이언트 낙관적 업데이트(Optimistic UI), Read-your-writes 보장 |
| **금융 예시** | "방금 송금했는데 잔액이 안 변했어요" → 클라이언트에서 즉시 차감 표시 + 뒤에서 동기화 |

## 2. Command / Query 모델 스키마 불일치

| 항목 | 내용 |
|------|------|
| **문제** | Write 쪽 스키마가 변경됐는데 Read 쪽 프로젝션이 업데이트 안 된 경우 |
| **왜 발생** | 두 모델이 독립적으로 진화하면서 불일치 발생 |
| **해결** | 이벤트 버전 관리, 프로젝션 재구축(replay) 파이프라인 마련, 블루-그린 프로젝션 전환 |
| **트레이드오프** | 프로젝션 재구축 시 대량 이벤트 재처리 → 시간/리소스 소모 |
