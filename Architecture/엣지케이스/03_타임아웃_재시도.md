# 타임아웃과 재시도 엣지케이스

## 1. 비멱등 요청 재시도로 이중 처리

| 항목 | 내용 |
|------|------|
| **문제** | 재시도하면 안 되는 요청(비멱등 POST)을 무분별하게 재시도 |
| **왜 발생** | 결제 생성 등 비멱등 요청을 재시도하면 이중 결제 발생 |
| **해결** | 멱등 요청만 재시도, 비멱등 요청은 idempotency-key 필수 |
| **금융 예시** | 결제 API 타임아웃 → 클라이언트가 재시도 → 서버에서는 첫 번째 요청도 성공 처리 → 이중 결제 |

## 2. Thundering Herd (재시도 폭풍)

| 항목 | 내용 |
|------|------|
| **문제** | 장애 복구 시 모든 클라이언트가 동시에 재시도 |
| **왜 발생** | 고정된 재시도 간격을 사용하면 복구 시점에 요청이 한꺼번에 몰림 |
| **해결** | Exponential backoff + jitter 적용 (랜덤 지연으로 재시도 시점 분산) |
| **jitter를 쓰는 이유** | backoff만 쓰면 같은 시점에 시작한 클라이언트들이 동일 간격으로 재시도 → 여전히 몰림 |
