# Service Discovery 엣지케이스

## 1. False Negative — 살아있는데 헬스체크 실패

| 항목 | 내용 |
|------|------|
| **문제** | 서비스가 정상인데 헬스체크만 실패하여 인스턴스가 제거됨 |
| **왜 발생** | 네트워크 일시 불안정, 헬스체크 엔드포인트만 느려지는 경우 |
| **해결** | 헬스체크 다중화(TCP + HTTP + 비즈니스 로직 체크), 연속 N회 실패 후 제거, grace period 설정 |
| **트레이드오프** | 체크 조건이 느슨하면 죽은 인스턴스에 트래픽이 감, 엄격하면 정상 인스턴스가 제거됨 |

## 2. 좀비 인스턴스

| 항목 | 내용 |
|------|------|
| **문제** | 프로세스는 살아있지만 실제 응답 불가 |
| **왜 발생** | GC 정지, 스레드 풀 고갈, DB 커넥션 풀 소진 등 |
| **해결** | Liveness + Readiness 프로브 분리, 실제 비즈니스 로직을 포함한 deep health check |
| **금융 예시** | 결제 서비스가 DB 커넥션 풀 고갈로 응답 불가인데 TCP 헬스체크는 통과 → 결제 실패 급증 |
