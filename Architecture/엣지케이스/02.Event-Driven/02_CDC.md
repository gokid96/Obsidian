# CDC (Change Data Capture) 엣지케이스

## 1. DB 스키마 변경 시 파이프라인 깨짐

| 항목         | 내용                                                                     |
| ---------- | ---------------------------------------------------------------------- |
| **문제**     | 바이너리 로그 포맷이 변경되거나 컬럼이 추가/삭제되면 커넥터가 파싱 실패                               |
| **왜 발생**   | CDC 커넥터는 특정 스키마 기준으로 동작하므로, 스키마 변경에 취약                                 |
| **해결**     | 스키마 레지스트리 도입, 하위 호환성 보장하는 스키마 진화(evolution) 전략, 배포 전 CDC 파이프라인 호환성 테스트 |
| **트레이드오프** | 스키마 레지스트리 운영 비용 추가, 스키마 변경 속도 제한                                       |

## 2. CDC 커넥터 재시작 시 offset 관리

| 항목         | 내용                                                           |
| ---------- | ------------------------------------------------------------ |
| **문제**     | Debezium 등 커넥터가 죽었다 살아날 때 어디까지 읽었는지 유실                       |
| **왜 발생**   | offset 기록이 유실되면 이벤트 중복 발행 또는 누락                              |
| **해결**     | Kafka Connect의 offset 저장소 활용, 스냅샷 + 스트리밍 복구 전략, 소비자 측 멱등성 보장 |
| **트레이드오프** | 스냅샷 복구 시 대량 이벤트 재발행 → 하류 서비스 부하                              |
