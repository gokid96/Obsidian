# Dead Letter Queue (DLQ) 엣지케이스

## 1. 재처리 시 순서 보장 문제

| 항목 | 내용 |
|------|------|
| **문제** | DLQ에 쌓인 순서와 원래 비즈니스 순서가 다를 수 있음 |
| **왜 발생** | 여러 파티션/토픽에서 실패한 메시지가 하나의 DLQ에 섞여 들어감 |
| **해결** | 재처리 시 타임스탬프/시퀀스 기반 정렬, 또는 순서 무관하게 처리 가능하도록 멱등성 보장 |
| **트레이드오프** | 순서 보장하려면 재처리 속도 저하, 무시하면 데이터 정합성 이슈 가능 |

## 2. DLQ 자체가 가득 차는 경우

| 항목 | 내용 |
|------|------|
| **문제** | 대량 장애 시 실패 메시지가 폭발적으로 증가 |
| **왜 발생** | 하위 서비스 전면 장애 등으로 대부분의 메시지가 처리 실패 |
| **해결** | DLQ 모니터링 + 알림 체계, DLQ 용량 별도 관리, 수동 개입 프로세스 문서화 |
| **금융 예시** | 결제 이벤트가 DLQ에 수만 건 쌓임 → 자동 재처리로 이중 결제 위험 → 반드시 수동 검증 후 재처리 |
