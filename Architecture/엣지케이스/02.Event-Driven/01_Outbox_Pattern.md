# Outbox Pattern 엣지케이스

## 1. Outbox 테이블 무한 증가로 DB 부하

| 항목         | 내용                                                            |
| ---------- | ------------------------------------------------------------- |
| **문제**     | Outbox 테이블이 계속 쌓여 DB 부하 증가                                    |
| **왜 발생**   | 발행 완료된 이벤트를 즉시 삭제하지 않거나, 발행 실패 이벤트가 누적                        |
| **해결**     | 발행 완료 후 배치 삭제, TTL 기반 정리, 또는 CDC 방식으로 전환하여 Outbox 테이블 자체를 경량화 |
| **트레이드오프** | 배치 삭제 주기가 길면 DB 부하, 짧으면 삭제 작업 자체가 부하                          |

## 2. 폴링 주기 설정 딜레마

| 항목         | 내용                                                              |
| ---------- | --------------------------------------------------------------- |
| **문제**     | 폴링 주기가 짧으면 DB 부하, 길면 이벤트 전달 지연                                  |
| **왜 발생**   | Outbox 테이블을 주기적으로 조회해야 하는 구조적 한계                                |
| **해결**     | CDC(Change Data Capture)로 전환하면 폴링 불필요, 또는 적응형 폴링(이벤트 많으면 주기 단축) |
| **트레이드오프** | CDC는 인프라 복잡도 증가(Debezium 등 추가 컴포넌트 필요)                          |
