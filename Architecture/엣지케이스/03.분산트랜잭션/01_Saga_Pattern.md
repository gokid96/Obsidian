# Saga Pattern 엣지케이스

## 1. 보상 트랜잭션 자체가 실패

| 항목 | 내용 |
|------|------|
| **문제** | 보상 로직도 네트워크 호출이므로 실패 가능 |
| **왜 발생** | 보상 대상 서비스가 장애이거나 네트워크 불안정 |
| **해결** | 보상 트랜잭션에 재시도 + 멱등성 보장, 최종 실패 시 수동 개입 큐(Dead Letter) + 운영자 알림 |
| **금융 예시** | 출금 성공 → 입금 실패 → 출금 환불(보상) 실패 → 돈이 사라진 상태 → 반드시 복구 필요 |

## 2. Isolation 부재 — 중간 상태 dirty read

| 항목 | 내용 |
|------|------|
| **문제** | 보상 실행 전 중간 상태 데이터를 다른 트랜잭션이 읽어버림 |
| **왜 발생** | Saga는 ACID 중 Isolation을 보장하지 않음 |
| **해결** | 시맨틱 락(상태 필드에 "처리중" 마킹), 상태 머신 기반 설계, 비관적 읽기 방지 |
| **금융 예시** | 송금 중 잔액 조회 → "출금은 됐는데 입금 전" 상태의 잔액이 보임 → 사용자 혼란 |

## 3. 오케스트레이터 장애 시 Saga 복구

| 항목 | 내용 |
|------|------|
| **문제** | 오케스트레이터가 죽으면 진행 중이던 Saga 상태 유실 |
| **왜 발생** | 오케스트레이터가 상태를 메모리에만 들고 있는 경우 |
| **해결** | Saga 상태를 영속 저장소(DB)에 기록, 재시작 시 미완료 Saga 스캔 후 이어서 처리 |
| **트레이드오프** | 매 스텝마다 DB 쓰기 → 성능 오버헤드, 하지만 금융에서는 필수 |
