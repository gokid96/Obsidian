
## 기본 개념
- **Cache Stampede** (= Thundering Herd, Cache Avalanche)
- 인기 있는 캐시 키가 만료되는 순간, **수백~수천 개의 동시 요청이 DB로 몰리는 현상**
- DB에 과부하 → 장애 발생 가능

## 문제 상황

```
시간 T: "hot_product:1" 캐시 만료
         ↓
요청 1 → Cache Miss → DB 조회
요청 2 → Cache Miss → DB 조회
요청 3 → Cache Miss → DB 조회
  ...
요청 N → Cache Miss → DB 조회  ← 동시에 N개가 DB를 침
```

## 해결 패턴

### 1. Mutex Lock (분산 락)
캐시 miss 시 **하나의 요청만 DB를 조회**하고, 나머지는 대기.

```python
import time

def get_with_lock(key: str) -> dict:
    # 1. 캐시 조회
    cached = redis.get(key)
    if cached:
        return json.loads(cached)
    
    # 2. 락 획득 시도
    lock_key = f"lock:{key}"
    if redis.set(lock_key, "1", nx=True, ex=5):  # 5초 타임아웃
        try:
            # 3. 락 획득 성공 → DB 조회 후 캐시 저장
            data = db.find(key)
            redis.setex(key, 1800, json.dumps(data))
            return data
        finally:
            redis.delete(lock_key)
    else:
        # 4. 락 획득 실패 → 잠시 대기 후 재시도
        time.sleep(0.1)
        return get_with_lock(key)  # 재귀 (실무에서는 루프 + 최대 재시도)
```

```java
// Redisson 분산 락 사용
public Product getProduct(String productId) {
    String key = "product:" + productId;
    Product cached = cache.get(key);
    if (cached != null) return cached;
    
    RLock lock = redisson.getLock("lock:" + key);
    try {
        lock.lock(5, TimeUnit.SECONDS);
        
        // Double-check: 대기하는 동안 다른 스레드가 이미 캐싱했을 수 있음
        cached = cache.get(key);
        if (cached != null) return cached;
        
        Product product = productRepository.findById(productId);
        cache.set(key, product, Duration.ofMinutes(30));
        return product;
    } finally {
        lock.unlock();
    }
}
```

### 2. Logical Expiration (논리적 만료)
캐시 자체는 만료하지 않되, **논리적 만료 시간**을 데이터에 포함. 만료되면 백그라운드에서 갱신.

```python
import threading

def get_with_logical_expiry(key: str) -> dict:
    cached = redis.get(key)
    
    if cached:
        data = json.loads(cached)
        
        if data["expires_at"] > time.time():
            return data["value"]  # 아직 유효
        
        # 논리적으로 만료됨 → 백그라운드에서 갱신
        if redis.set(f"refresh:{key}", "1", nx=True, ex=10):
            threading.Thread(
                target=refresh_cache, 
                args=(key,)
            ).start()
        
        return data["value"]  # stale 데이터라도 즉시 반환
    
    # 캐시 자체가 없으면 DB 조회
    return fetch_and_cache(key)

def refresh_cache(key: str):
    """백그라운드에서 캐시 갱신"""
    data = db.find(key)
    cache_data = {
        "value": data,
        "expires_at": time.time() + 1800  # 30분 후 논리적 만료
    }
    redis.set(key, json.dumps(cache_data))  # TTL 없이 저장
    redis.delete(f"refresh:{key}")
```

### 3. Probabilistic Early Expiration (확률적 조기 만료)
TTL 만료 **전에** 확률적으로 미리 갱신. 만료 시점에 가까울수록 갱신 확률 증가.

```python
import random
import math

def get_with_early_refresh(key: str, beta: float = 1.0) -> dict:
    cached = redis.get(key)
    ttl = redis.ttl(key)
    
    if cached and ttl > 0:
        # XFetch 알고리즘: 만료가 가까울수록 갱신 확률 증가
        expiry_gap = -beta * math.log(random.random())
        
        if ttl > expiry_gap:
            return json.loads(cached)  # 아직 여유 있음
        
        # 확률적으로 조기 갱신 → 하나의 요청만 갱신하게 됨
    
    data = db.find(key)
    redis.setex(key, 1800, json.dumps(data))
    return data
```

### 4. Cache Warming (사전 로딩)
인기 키가 만료되기 전에 **스케줄러로 미리 갱신**.

```python
# 별도 스케줄러에서 주기적으로 실행
@scheduler.every(minutes=25)  # TTL(30분)보다 짧은 주기
def warm_hot_caches():
    hot_keys = ["product:bestseller", "feed:trending", "config:app"]
    for key in hot_keys:
        data = db.find(key)
        redis.setex(key, 1800, json.dumps(data))
```

## 패턴 비교

| 패턴 | 복잡도 | Stale 데이터 | DB 보호 | 적합한 상황 |
|------|--------|-------------|---------|------------|
| Mutex Lock | 중간 | 없음 | 강함 | 일관성 중요 |
| Logical Expiration | 높음 | 일시적 허용 | 강함 | 응답 속도 중요 |
| Probabilistic | 중간 | 없음 | 보통 | 범용 |
| Cache Warming | 낮음 | 없음 | 강함 | 인기 키가 예측 가능 |

## 실무 포인트

> [!tip] 추천 조합
> - **Mutex Lock + TTL jitter**: 가장 범용적
> - TTL에 랜덤값 추가하여 동시 만료 방지: `TTL = base_ttl + random(0, 300)`

```python
import random

def set_with_jitter(key: str, value: str, base_ttl: int = 1800):
    jitter = random.randint(0, 300)  # 0~5분 랜덤 추가
    redis.setex(key, base_ttl + jitter, value)
```
