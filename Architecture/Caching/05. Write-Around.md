
## 기본 개념
- 데이터를 **DB에만 직접 쓰고**, 캐시는 건드리지 않음
- 다음 읽기 요청에서 cache miss가 발생하면 그때 캐시에 로드
- 자주 읽히지 않는 데이터의 불필요한 캐싱을 방지

## 동작 흐름

```
[쓰기]
[Client] → [App] → [DB에만 쓰기] → 완료
                    (캐시는 무시)

[읽기] — Cache-Aside와 동일
[Client] → [App] → [Cache 조회]
                     ├── Hit → 반환
                     └── Miss → DB 조회 → 캐시 저장 → 반환
```

## 코드 예시

```python
class WriteAroundCache:
    
    def write(self, key: str, data: dict):
        """DB에만 쓰기 — 캐시는 건드리지 않음"""
        db.save(key, data)
        
        # 기존 캐시가 있다면 무효화 (stale 방지)
        redis.delete(f"cache:{key}")
    
    def read(self, key: str) -> dict:
        """Cache-Aside 방식으로 읽기"""
        cached = redis.get(f"cache:{key}")
        if cached:
            return json.loads(cached)
        
        data = db.find(key)
        redis.setex(f"cache:{key}", 1800, json.dumps(data))
        return data
```

```java
@Service
public class WriteAroundService {
    
    public void createLog(LogEntry entry) {
        // DB에만 저장, 캐시에는 넣지 않음
        logRepository.save(entry);
        // 로그는 거의 다시 읽히지 않으므로 캐싱 불필요
    }
    
    public void updateUser(String userId, User user) {
        // DB에 저장
        userRepository.save(user);
        // 기존 캐시 무효화 (stale data 방지)
        cache.delete("user:" + userId);
    }
    
    @Cacheable("users")  // 읽기는 Cache-Aside
    public User getUser(String userId) {
        return userRepository.findById(userId);
    }
}
```

## 장점
- 자주 읽히지 않는 데이터로 캐시가 오염되지 않음 → **메모리 효율적**
- 쓰기가 단순 (DB만 쓰면 됨)
- 로그, 감사 기록 등 "쓰기 위주" 데이터에 적합

## 단점
- 쓰기 직후 읽기 시 항상 cache miss → **읽기 지연**
- 자주 읽히는 데이터에 적용하면 성능 저하

## 실무 포인트

> [!tip] 언제 쓰나?
> - 로그, 감사(audit) 기록 등 쓰기 후 거의 읽지 않는 데이터
> - 대량 쓰기 작업 (배치 import 등)에서 캐시 오염 방지
> - Cache-Aside 읽기 패턴과 자연스럽게 조합

> [!note] Write-Around + 캐시 무효화
> 이미 캐시에 있는 데이터를 업데이트할 때는 반드시 기존 캐시를 삭제해야 한다.
> 그렇지 않으면 stale data가 TTL 만료까지 남아 있게 됨.

## 쓰기 패턴 비교 요약

| 패턴 | 쓰기 대상 | 쓰기 속도 | 일관성 | 적합한 경우 |
|------|----------|----------|--------|------------|
| Write-Through | 캐시 + DB (동기) | 느림 | 강함 | 읽기 많고 일관성 중요 |
| Write-Behind | 캐시 → DB (비동기) | 빠름 | 약함 | 쓰기 빈번, 유실 허용 |
| Write-Around | DB만 | 보통 | 보통 | 쓰기 후 잘 안 읽힘 |
