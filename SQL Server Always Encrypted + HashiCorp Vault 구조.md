| 구성요소                            | 역할                       | 위치                   |
| ------------------------------- | ------------------------ | -------------------- |
| **CMK** (Column Master Key)     | CEK를 암호화하는 마스터 키         | Vault Transit        |
| **CEK** (Column Encryption Key) | 실제 데이터 암호화용 AES-256 키    | SQL Server (암호화된 상태) |
| **VaultCmkProvider**            | SqlClient ↔ Vault 통신 브리지 | 클라이언트 앱              |
| **SqlClient Driver**            | 자동 암복호화 + CEK 캐싱         | 클라이언트 앱              |
| **Transit Engine**              | CMK로 wrap/unwrap 수행      | Vault                |
### 데이터 흐름

#### Insert (암호화)

```
앱 → SqlClient → [CEK 캐시 확인]
                  │
                  ├─ 캐시 있음 → 바로 암호화 → DB 저장
                  │
                  └─ 캐시 없음 → Vault에 CEK unwrap 요청
                                 → CMK로 CEK 복호화
                                 → 평문 CEK 캐시
                                 → 데이터 암호화 → DB 저장
```

#### Select (복호화)

```
앱 → SqlClient → DB에서 암호문 조회
              → 캐시된 CEK로 복호화
              → 평문을 앱에 반환
```

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   클라이언트     │    │   SQL Server    │    │     Vault       │

│  ✅ 평문 데이터  │    │  ❌ 평문 없음   │    │  ✅ CMK 평문    │
│  ✅ 평문 CEK    │    │  ✅ 암호 CEK    │    │  ❌ CEK 없음    │
│     (캐시)      │    │  ✅ 암호 데이터 │    │  ❌ 데이터 없음 │

       신뢰 필요          DBA 불신 가능        독립 관리
```

### 현재 구현의 한계와 개선 포인트

현재 아키텍처는 POC 수준에서 동작하지만, 실무 투입 전 다음 항목의 개선이 필요

#### 🔴 필수 개선 (보안/성능 직결)

| #   | 항목               | 현재 상태                      | 목표                                                             | 이유                                                              |
| --- | ---------------- | -------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------- |
| 1   | **CEK 내부 캐시**    | 없음                         | Provider 내부에 TTL 기반 캐시 구현                                      | 커스텀 Provider는 SqlClient 자동 캐시가 **비활성화**되어 매 쿼리마다 Vault 호출 발생 가능 |
| 2   | **Key Path 검증**  | `transit/keys/` 프리픽스 검증 없음 | 화이트리스트 기반 strict 검증                                            | DBA가 `KEY_PATH`를 조작해 공격자 Vault로 우회 가능                           |
| 3   | **메타데이터 서명키 분리** | 소스코드에 HMAC 키 하드코딩          | Vault Transit의 `sign/verify` API 사용 (MS 표준 패턴) Windows 인증서 저장소 | 하드코딩 키는 DLL 디컴파일로 즉시 노출, 서명이 사실상 무의미                            |

#### 🟡 권장 개선 (안정성/호환성)

| #   | 항목                     | 현재 상태                                       | 목표                                    | 이유                                 |
| --- | ---------------------- | ------------------------------------------- | ------------------------------------- | ---------------------------------- |
| 4   | **CipherText 저장 방식**   | `Encoding.UTF8.GetBytes()`                  | Base64 또는 바이너리 그대로                    | Vault 키 로테이션(v1→v2) 시 자동 rewrap 불가 |
| 5   | **sync-over-async 처리** | `GetAwaiter().GetResult()` 직접 호출            | `Task.Run()`으로 감싸기                    | WinForms UI 스레드에서 데드락 위험           |
| 6   | **Provider 등록 방식**     | `RegisterColumnEncryptionKeyStoreProviders` | `RegisterOnConnection` 또는 `OnCommand` | 전역 등록 시 SqlClient의 내장 CEK 캐시가 꺼짐   |

#### 🟢 운영 전 필수 (배포/인프라)

| #   | 항목                             | 현재 상태                       | 목표                                | 이유                       |
| --- | ------------------------------ | --------------------------- | --------------------------------- | ------------------------ |
| 7   | **Vault 전송 암호화**               | `http://192.168.14.31:8202` | `https://` + 인증서 검증               | CEK 평문이 네트워크 평문으로 흐름     |
| 8   | **자격증명 외부화**                   | RoleId/SecretId 소스코드 하드코딩   | 환경변수 / User Secrets / Vault Agent | 소스 유출 시 Vault 접근권한 전체 노출 |
| 9   | **SQL TrustServerCertificate** | `True` (개발용)                | 운영 인증서 정식 검증                      | MITM 공격                  |
