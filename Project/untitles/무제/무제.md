```javascript
    http_req_failed: ['rate<0.01'],

  check(res, {
    'status 200': (r) => r.status === 200,
    'response < 500ms': (r) => r.timings.duration < 500,
```

## 1단계 — 프로젝트 확장성 분석 (베이스라인 측정)

아무것도 건드리지 않은 상태에서 현재 서버가 어디까지 버티는지 측정한다. 이 수치가 이후 모든 개선의 기준점이 된다.

### 측정 대상 API

공개 워크스페이스 조회(`/api/v1/public/{slug}`)를 주 타깃으로 선정한다. 비로그인 사용자가 접근하는 엔드포인트로 가장 많은 트래픽이 몰릴 수 있는 지점이다.

### 측정 절차

```bash
# 1. Grafana 대시보드 열어두기 (EC2 CPU, JVM 힙, DB 커넥션 패널)
# 2. CloudWatch RDS 모니터링 탭 열어두기
# 3. 애플리케이션 로그 tail
tail -f logs/application.log | grep "Hibernate"

# 4. k6 실행
k6 run --out json=baseline_result.json k6/public_workspace.js
```

### Grafana에서 동시에 확인할 패널

```
- EC2 CPU Usage (%)
- JVM Heap Used (MB)
- HikariCP Active Connections (DB 커넥션 풀)
- HTTP Request Duration (p50, p95, p99)
- HTTP Requests per Second (TPS)
```

### 측정하면서 확인할 것

```
k6 부하가 올라가는 동안

1. EC2 CPU가 먼저 올라가는가?
   → 애플리케이션 코드(연산)가 병목

2. RDS CPU가 먼저 올라가는가?
   → 쿼리/인덱스가 병목

3. HikariCP 커넥션이 고갈되는가?
   → DB 커넥션 풀 설정이 병목

4. 로그에 쿼리가 몇 번 찍히는가?
   → 요청 1번당 쿼리 N번이면 N+1 의심
```

### 베이스라인 기록표

|지표|측정값|비고|
|---|---|---|
|TPS (vus 100 기준)||k6 출력|
|p50 응답시간|ms|k6 출력|
|p95 응답시간|ms|k6 출력|
|p99 응답시간|ms|k6 출력|
|에러율|%|k6 출력|
|EC2 CPU 최고점|%|Grafana|
|RDS CPU 최고점|%|CloudWatch|
|HikariCP 최대 사용 커넥션|개|Grafana|
|요청 1건당 쿼리 수|번|Hibernate 로그|

### 분석 결론 도출

측정 결과를 보고 다음 질문에 답한다.

```
- 병목 지점이 EC2인가, RDS인가?
- 단일 서버 최대 TPS 한계는 몇인가?
- 요청당 쿼리가 몇 번 나가는가? (N+1 여부)
- 어떤 지표를 먼저 개선해야 하는가?
```

이 분석 결과가 2~5단계의 개선 순서를 결정하는 근거가 된다.

## 3단계 — 동시성 문제 재현 및 해결

### Before 측정 — 동시 수정 시나리오 재현

Post 엔티티에 `@Version`이 선언되어 있지만 실제 충돌 처리가 되는지 확인한다.

```javascript
// k6/concurrent_update.js
import http from 'k6/http';
import { check } from 'k6';

export const options = {
  vus: 50,
  duration: '10s',
};

export default function () {
  const payload = JSON.stringify({
    title: `동시 수정 테스트 ${Date.now()}`,
    content: '내용'
  });
  const params = {
    headers: {
      'Content-Type': 'application/json',
      'Cookie': 'SESSION=your-session-id'
    }
  };

  // 동일한 postId에 50명이 동시 수정 요청
  const res = http.patch(
    'http://your-ec2-ip/api/v1/workspaces/1/posts/1',
    payload,
    params
  );

  check(res, {
    '200 또는 409': (r) => r.status === 200 || r.status === 409,
  });
}
```

```bash
k6 run --out json=before_concurrency.json k6/concurrent_update.js

# 확인할 것
# 1. 응답이 전부 200인가? → 충돌 감지 안 됨 (Lost Update 발생)
# 2. DB에서 최종 version 값이 50인가 아닌가?
# 3. 애플리케이션 로그에 OptimisticLockException이 찍히는가?
```

```sql
-- 테스트 후 실제 데이터 확인
SELECT post_id, title, version FROM post WHERE post_id = 1;
-- version이 50이 아니면 Lost Update 발생한 것
```

Grafana에서 이 시점 에러율, 응답시간 기록

### 문제 확인 후 개선 적용

```java
// GlobalExceptionHandler.java — 낙관적 락 예외 처리 추가
@ExceptionHandler(ObjectOptimisticLockingFailureException.class)
public ResponseEntity<ApiResponse<?>> handleOptimisticLock(
        ObjectOptimisticLockingFailureException e) {
    return ResponseEntity.status(HttpStatus.CONFLICT)
            .body(ApiResponse.error("다른 사용자가 수정 중입니다. 다시 시도해주세요."));
}
```

### After 측정

```bash
k6 run --out json=after_concurrency.json k6/concurrent_update.js

# 1. 충돌 시 409 응답이 오는가?
# 2. DB version 값이 정확히 증가했는가?
# 3. Lost Update가 사라졌는가?
```


### Before / After 수치 비교

|지표|Before (실측)|After (실측)|결과|
|---|---|---|---|
|동시 50건 중 충돌 감지|0건 (전부 200)|N건 409 응답|Lost Update 제거|

```java
// PublicViewService.java — 개선 후
private List<Post> getVisiblePosts(Workspace workspace) {
    // Before: post 조회 + folder 별도 조회 + LAZY 로딩 N번
    // After: 한 번의 쿼리로 post + folder + author 모두 조회
    List<Post> allPosts = postRepository.findAllWithFolderAndAuthorByWorkspaceId(
            workspace.getWorkspaceId());

    // folderMap 별도 조회 불필요 — post 안에 folder 이미 포함
    if (Boolean.TRUE.equals(workspace.getPublishAll())) {
        return allPosts.stream()
                .filter(p -> !Boolean.TRUE.equals(p.getIsExcluded()))
                .toList();
    }
    // ... 이하 동일
}
```

### JWT 전환

```java
// JwtProvider.java
@Component
public class JwtProvider {

    @Value("${jwt.secret}")
    private String secretKey;

    private static final long ACCESS_TOKEN_EXPIRATION = 1000L * 60 * 60; // 1시간

    public String generateToken(Long userId) {
        return Jwts.builder()
                .subject(String.valueOf(userId))
                .issuedAt(new Date())
                .expiration(new Date(System.currentTimeMillis() + ACCESS_TOKEN_EXPIRATION))
                .signWith(Keys.hmacShaKeyFor(secretKey.getBytes()))
                .compact();
    }

    public Long getUserId(String token) {
        return Long.parseLong(
            Jwts.parser()
                .verifyWith(Keys.hmacShaKeyFor(secretKey.getBytes()))
                .build()
                .parseSignedClaims(token)
                .getPayload()
                .getSubject()
        );
    }
}
```

```java
// OAuth2AuthenticationSuccessHandler.java — JWT 발급으로 변경
```

```java
    public RedisCacheManager redisCacheManager(RedisConnectionFactory factory) {
```
