## 전체 로드맵


## 2단계 — DB 인덱스 최적화

### 타깃 1: PostService.getMemberOrThrow — 매 요청마다 2번 쿼리

현재 PostService에서 권한 확인 시 매번 Workspace와 User를 각각 조회한 뒤 멤버를 찾습니다.

```java
// 현재 코드 (PostService.java)
private WorkspaceMember getMemberOrThrow(Long userId, Long workspaceId) {
    Workspace workspace = workspaceRepository.findById(workspaceId)  // 쿼리 1번
            .orElseThrow(() -> new BusinessException(ErrorCode.WORKSPACE_NOT_FOUND));
    Users user = userRepository.findById(userId)                      // 쿼리 2번
            .orElseThrow(() -> new BusinessException(ErrorCode.USER_NOT_FOUND));

    return workspaceMemberRepository.findByWorkspaceAndUser(workspace, user)  // 쿼리 3번
            .orElseThrow(() -> new BusinessException(ErrorCode.ACCESS_DENIED));
}
```

반면 FolderService는 이미 최적화된 방식을 사용합니다.

```java
// FolderService.java — 이미 최적화됨 (1번 쿼리)
return workspaceMemberRepository.findByWorkspaceWorkspaceIdAndUserUserId(workspaceId, userId)
        .orElseThrow(() -> new BusinessException(ErrorCode.ACCESS_DENIED));
```

**개선 방향**: PostService, WorkspaceService의 getMemberOrThrow를 FolderService 방식으로 통일합니다.

```java
// 개선 후 (PostService.java)
private WorkspaceMember getMemberOrThrow(Long userId, Long workspaceId) {
    return workspaceMemberRepository
            .findByWorkspaceWorkspaceIdAndUserUserId(workspaceId, userId)
            .orElseThrow(() -> new BusinessException(ErrorCode.ACCESS_DENIED));
}
```

**인덱스 추가**:

```sql
-- workspace_member 테이블에 복합 인덱스 추가

    ON workspace_member(workspace_id, user_id);

-- post 테이블 — workspaceId + postId 조회 빈번

-- folder 테이블 — workspaceId + parentId(null) 루트 조회
```

## 3단계 — 동시성 문제 재현 및 해결

### 현재 상태 파악

Post 엔티티에 `@Version`이 이미 선언되어 있습니다.

```java
// Post.java — 이미 선언됨
@Version
private Long version;
```

하지만 실제로 동시 수정 충돌 시나리오를 테스트하고 수치화한 적은 없을 것입니다. 이 단계에서는 **실제로 충돌을 재현하고 낙관적 락이 동작함을 증명**합니다.

### Before — 동시 수정 시나리오 재현

```javascript
// k6/concurrent_post_update.js
import http from 'k6/http';
import { check } from 'k6';

export const options = {
  vus: 50,
  duration: '10s',
};

export default function () {
  const payload = JSON.stringify({ title: `수정된 제목 ${Date.now()}`, content: '내용' });
  const params = { headers: { 'Content-Type': 'application/json', 'Cookie': 'SESSION=your-session' } };

  // 동일한 게시글에 동시 수정 요청
  const res = http.patch('http://your-ec2-ip/api/v1/workspaces/1/posts/1', payload, params);

  check(res, {
    'success or optimistic lock': (r) => r.status === 200 || r.status === 409,
  });
}
```

### 낙관적 락 동작 확인

```java
// 현재 updatePost — saveAndFlush 사용 중 (낙관적 락 즉시 감지)
return PostResponseDTO.from(postRepository.saveAndFlush(post));
// 동시 수정 시 ObjectOptimisticLockingFailureException 발생
```

예외 처리 추가:

```java
// GlobalExceptionHandler.java에 추가
@ExceptionHandler(ObjectOptimisticLockingFailureException.class)
public ResponseEntity<ApiResponse<?>> handleOptimisticLock(ObjectOptimisticLockingFailureException e) {
    return ResponseEntity.status(HttpStatus.CONFLICT)
            .body(ApiResponse.error("다른 사용자가 수정 중입니다. 다시 시도해주세요."));
}
```

### 수치화 결과 예시

|항목|Before|After|결과|
|---|---|---|---|
|동시 50명 수정 시 데이터 정합성|불보장 (Lost Update)|보장|낙관적 락 동작 확인|
|충돌 감지 응답|200 (데이터 덮어쓰기)|409 Conflict|정합성 오류 0건|

### 포트폴리오 문장

Post 엔티티에 낙관적 락(@Version) 적용 후 동시 50명 수정 시나리오를 k6로 재현. Lost Update 문제를 제거하고 충돌 시 409 응답으로 사용자에게 명시적 피드백 제공

## 4단계 — N+1 제거 및 비동기 처리

### 타깃 1: PublicViewService — getVisiblePosts N+1 문제

현재 공개 워크스페이스 조회 흐름입니다.

```java
// PublicViewService.java — 현재 코드
private List<Post> getVisiblePosts(Workspace workspace) {
    // 1번: 게시글 전체 조회
    List<Post> allPosts = postRepository.findAllWithAuthorByWorkspaceWorkspaceId(
            workspace.getWorkspaceId());

    // 2번: 폴더 전체 조회 (별도 쿼리)
    Map<Long, Folder> folderMap = folderRepository
            .findAllByWorkspaceWorkspaceId(workspace.getWorkspaceId())
            .stream()
            .collect(Collectors.toMap(Folder::getFolderId, f -> f));

    // 이후 루프에서 post.getFolder() 호출 시
    // folder가 LAZY이므로 추가 쿼리 발생 가능
    for (Post post : allPosts) {
        Folder folder = post.getFolder(); // LAZY 로딩
        // ...
    }
}
```

Post → Folder가 LAZY 로딩이고, 루프 안에서 `post.getFolder()`를 호출하면 N+1이 발생할 수 있습니다.

**개선**: Post 조회 시 Folder를 함께 Fetch Join합니다.

```java
// PostRepository.java에 추가
@Query("SELECT p FROM Post p " +
       "LEFT JOIN FETCH p.folder " +
       "LEFT JOIN FETCH p.author " +
       "WHERE p.workspace.workspaceId = :workspaceId")
List<Post> findAllWithFolderAndAuthorByWorkspaceId(@Param("workspaceId") Long workspaceId);
```

```java
// PublicViewService.java — 개선 후
private List<Post> getVisiblePosts(Workspace workspace) {
    // 게시글 + 폴더 + 작성자를 한 번에 조회
    List<Post> allPosts = postRepository.findAllWithFolderAndAuthorByWorkspaceId(
            workspace.getWorkspaceId());
    // 폴더 별도 조회 불필요 — Post 안에 이미 포함됨
    // ...
}
```

### JWT로 전환

```java
// build.gradle에 추가
implementation 'io.jsonwebtoken:jjwt-api:0.12.3'
runtimeOnly 'io.jsonwebtoken:jjwt-impl:0.12.3'
runtimeOnly 'io.jsonwebtoken:jjwt-jackson:0.12.3'
```

```java
// JwtProvider.java
@Component
public class JwtProvider {

    @Value("${jwt.secret}")
    private String secretKey;

    private static final long ACCESS_TOKEN_EXPIRATION = 1000 * 60 * 60; // 1시간

    public String generateToken(Long userId) {
        return Jwts.builder()
                .subject(String.valueOf(userId))
                .issuedAt(new Date())
                .expiration(new Date(System.currentTimeMillis() + ACCESS_TOKEN_EXPIRATION))
                .signWith(Keys.hmacShaKeyFor(secretKey.getBytes()))
                .compact();
    }

    public Long getUserId(String token) {
        return Long.parseLong(
            Jwts.parser()
                .verifyWith(Keys.hmacShaKeyFor(secretKey.getBytes()))
                .build()
                .parseSignedClaims(token)
                .getPayload()
                .getSubject()
        );
    }
}
```

### 트레이드오프 정리

|항목|세션 (현재)|JWT (변경 후)|
|---|---|---|
|스케일 아웃|서버마다 세션 불일치|Stateless, 어느 서버나 동일|
|OAuth2 호환|자연스럽게 동작|SuccessHandler 수정 필요|
|SPOF|Redis 단일 장애점|없음|
|토큰 강제 만료|즉시 가능 (세션 삭제)|만료 전까지 유효|
|탈취 대응|세션 즉시 삭제|Blacklist 별도 필요|

### 포트폴리오 문장

EC2 2대 스케일 아웃 후 ALB 환경에서 세션 불일치로 로그인 풀림 현상을 직접 재현. Redis 세션 공유 도입 검토 과정에서 SPOF 리스크를 인식하고 JWT 기반 Stateless 인증으로 전환. OAuth2(Google/Kakao/Naver) 연동 유지하며 SuccessHandler에서 JWT 발급 구조로 재설계

## 7단계 — Redis 캐싱 도입 (Caffeine 불일치 해결)

### 문제 재현: 스케일 아웃 후 Caffeine 캐시 불일치

```
EC2-1: publicWorkspace 캐시 = { slug: "my-blog", posts: [...] }  (캐시됨)
EC2-2: publicWorkspace 캐시 = 없음 또는 다른 버전

사용자 A → ALB → EC2-1 → 캐시된 이전 데이터 반환
사용자 B → ALB → EC2-2 → DB에서 최신 데이터 반환

같은 URL인데 다른 응답 반환 확인
```

### Redis Remote 캐싱으로 전환

```java
// build.gradle에 추가 (JWT 전환 시 이미 Redis 의존성 있음)
implementation 'org.springframework.boot:spring-boot-starter-data-redis'
implementation 'org.springframework.data:spring-data-redis'
```

```java
// RedisCacheConfig.java
@Configuration
public class RedisCacheConfig {

    @Bean
    public RedisCacheManager redisCacheManager(RedisConnectionFactory factory) {
        RedisCacheConfiguration config = RedisCacheConfiguration.defaultCacheConfig()
                .entryTtl(Duration.ofMinutes(5))
                .serializeKeysWith(
                    RedisSerializationContext.SerializationPair
                        .fromSerializer(new StringRedisSerializer()))
                .serializeValuesWith(
                    RedisSerializationContext.SerializationPair
                        .fromSerializer(new GenericJackson2JsonRedisSerializer()));

        return RedisCacheManager.builder(factory)
                .cacheDefaults(config)
                .build();
    }
}
```

```java
// PublicViewService.java — Caffeine → Redis 전환
// Before
@Cacheable(value = "publicWorkspace", key = "#slug")

// After
@Cacheable(value = "publicWorkspace", key = "#slug", cacheManager = "redisCacheManager")
public PublicWorkspaceResponse getPublicWorkspace(String slug) {
    // 기존 로직 동일
}
```

### Untitles에서 발생 가능한 캐시 문제 및 해결

|문제|Untitles 시나리오|해결책|
|---|---|---|
|Cache Stampede|인기 블로그 slug 캐시 만료 시 동시 요청 폭주|Mutex Lock|
|Cache Penetration|존재하지 않는 slug로 반복 요청|Null 캐싱|
|Cache Avalanche|여러 slug 캐시 동시 만료|TTL 랜덤 지터|
|캐시 불일치|게시글 수정 후 캐시 미갱신|@CacheEvict|

```java
// 게시글 수정 시 해당 워크스페이스 공개 캐시 무효화
@CacheEvict(value = "publicWorkspace", key = "#slug", cacheManager = "redisCacheManager")
public void evictOnPostUpdate(String slug) { }

// TTL 랜덤 지터 (Cache Avalanche 방지)
long ttl = 300 + new Random().nextInt(60); // 300~360초
redisTemplate.expire("publicWorkspace::" + slug, ttl, TimeUnit.SECONDS);
```
