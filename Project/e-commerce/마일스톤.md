## D. 전 도메인 로직 대조 결론 (cf10b37 기준)

- balance/coupon/order·payment/product·stock/user·common: 핵심 로직·동시성 사실상 동일.
- 실제 "동작" 차이는 예외 타입(400 vs 500) 하나뿐. 나머지는 동등 결과의 구현 디테일.
- 공통 미해결(양쪽): 외부호출-in-tx(→STEP10 실배선 시 부활, createOrder가 여전히 tx 내 원격호출), getProducts N+1(→#52), 재고 다중락 비정렬 데드락(→보강 배정, 상품 ID 정렬).
- ★ 레퍼런스 git 로그 확인(HEAD=f950c1c, 종착점): 멱등/dedup 커밋 0건. 3대 정합성 이슈(보상 유실/결제 멱등/DLT 소실)는 최종 커밋까지 미해결 → 우리 STEP11 신설로 초과 대응. "더 따라가면 고쳐진다" 아님.
- 테스트: 레퍼런스가 더 촘촘(Repository/Service 분리/user). 우리는 lock·filter 테스트가 더 많음. 단 양쪽 다 사가 실패 시맨틱(재전달 멱등/롤백/DLT)은 미검증 → STEP11에서 보강.
- (STEP06 추가) 우리 개선분: FINISHED 발급 불가 처리, finishCoupon 명시 save, RedisKeyCleaner 선행 배치, SDR4 immediateWrites.
- (정리) 우리가 레퍼런스보다 나은 판단: 예외 400(vs 500), FINISHED 차단, 명시 save, 그리고 STEP11 정합성 하드닝. 레퍼런스는 학습 스코프상 정합성 3건을 의도적으로 미포함.
