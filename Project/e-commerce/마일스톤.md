# 레퍼런스 대비 차이 (개인 메모)
## A. 구조적으로 다른 점 (의도적)
| 항목 | 우리 | 레퍼런스 |
|---|---|---|
| 패키지 | feature-by-package | layer-by-package |
| Repository | 3-tier CoreRepository | 2-tier RepositoryImpl |
| 반환 타입 | Optional + 서비스 orElseThrow | 엔티티 직접 + impl orElseThrow |
| stock | product 하위 패키지 | 독립 도메인 |
| UserCoupon | CouponService 통합 | user 도메인 분리 |
| 메서드명 | Coupon.issue() | Coupon.publish() |
| 변경 영속화 | 명시 save() | dirty checking (내 시점에도 동일) |
| 캐시 DTO | @JsonCreator (불변) | @Setter + @NoArgsConstructor (가변) |
| 캐시 직렬화기 | GenericJacksonJsonRedisSerializer (Jackson3) | GenericJackson2... (Jackson2) |
| 테스트 Redis | 로컬 Redis(6379) 고정 | week7부터 Redis Testcontainer 전환 |
## B. 레퍼런스가 중간에 번복/변경한 것
- WithLock 네이밍 번복 → 우리는 findWithLockBy 고정 (postfix 통일 안 함).
- updateBalance → chargeBalance 리네임 → 우리 이미 최종.
- Message 도메인 생성 → Kafka 전환 시 제거 (#43 추출 / #47 제거).
- Outbox 구현 → 단순화 (#49 구현 후 정리).
- 캐시 delimiter 수정 → 리버트 (넷 제로) → 우리는 :: 고정, 스킵.
