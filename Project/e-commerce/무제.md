
Saga는 분산 트랜잭션 문제를 해결하는 방법이고, 
Saga가 제대로 동작하려면 각 단계의 실패에 대한 "보상 트랜잭션"이 필요하다.

### 1. 분산 트랜잭션

```
"분산 트랜잭션"
        ↓
하나의 비즈니스 작업이 여러 서비스/DB에 걸쳐 실행됨
        ↓
Order DB의 @Transactional만으로
Product DB / Coupon DB / Balance DB까지
ROLLBACK 할 수 없음
        ↓
"한쪽은 성공하고 다른 쪽은 실패하는 문제"
        ↓
Saga Pattern / 보상 트랜잭션
        ↓
예)
주문 생성
  ↓
재고 차감 성공
  ↓
결제 실패
  ↓
재고 복구
  ↓
주문 취소
```

네 프로젝트에서는:

```
Order Service
      ↓
Product Service
      ↓
Payment Service
      ↓
Balance / Coupon Service
```

처럼 여러 서비스가 연결되어 있기 때문에 발생하는 문제.

---

### 2. 이벤트 유실

```
"이벤트 유실"
        ↓
DB 저장과 Kafka 메시지 발행은 서로 다른 시스템
        ↓
주문 DB 저장 성공
        ↓
Kafka 발행 실패
        ↓
DB에는 주문이 있는데
Kafka에는 ORDER_CREATED 이벤트가 없음
        ↓
Payment Service가 주문 생성 사실을 모름
        ↓
Outbox Pattern
        ↓
별도의 Outbox 테이블에
"Kafka로 보내야 할 이벤트"를 DB에 먼저 저장
        ↓
주기적으로 Outbox를 조회
        ↓
Kafka로 이벤트 전송
        ↓
전송 성공 → 발행 완료 처리
```

예를 들면:

```
orders
┌─────────────────┐
│ order_id = 100  │
│ status = CREATED│
└─────────────────┘
          +
outbox
┌────────────────────────────┐
│ ORDER_CREATED              │
│ order_id = 100             │
│ payload = {...}            │
│ published = false          │
└────────────────────────────┘
```

Kafka 전송이 실패해도 Outbox에 남아있기 때문에 **다시 전송할 수 있다.**

네 프로젝트:

```
common/outbox
        ↓
이벤트를 DB에 기록
        ↓
Outbox Publisher
        ↓
      Kafka
```

---

### 3. 중복 이벤트

```
"중복 이벤트"
        ↓
Kafka 이벤트가 네트워크 문제 / Consumer 장애 등으로
다시 전달될 수 있음
        ↓
ORDER_CREATED
        ↓
Payment Service
        ↓
     결제 처리
        ↓
Consumer ACK 전에 장애 발생
        ↓
Kafka가 "처리 안 됐나?"라고 판단
        ↓
같은 ORDER_CREATED 다시 전달
        ↓
Payment Service가 또 결제
        ↓
중복 결제 발생 가능
        ↓
Idempotency(멱등성)
```

해결 방법:

```
이벤트
{
    eventId = "abc-123",
    orderId = 100
}
        ↓
     Consumer
        ↓
eventId = "abc-123"
이미 처리했는지 확인
        ↓
처리한 적 있음
        ↓
      무시
```

즉:

```
같은 이벤트 1번 처리 → 결제
같은 이벤트 2번 처리 → 무시
같은 이벤트 3번 처리 → 무시
```

**같은 이벤트를 여러 번 받아도 결과가 한 번 처리한 것과 같도록 만드는 것**이 멱등성이다.

---

### 4. 동시성

```
"동시성"
        ↓
여러 사용자가 같은 데이터를
동시에 변경하려고 함
        ↓
재고 1개
        ↓
사용자 A ─┐
          ├→ Product Service
사용자 B ─┘
        ↓
A → 재고 1 확인
B → 재고 1 확인
        ↓
A → 재고 차감
B → 재고 차감
        ↓
재고는 1개인데
주문은 2개 성공
        ↓
Race Condition
        ↓
Lock
```

대표적인 해결 방법:

```
동시성 문제
    ↓
┌───────────────┐
│ DB Lock       │
│               │
│ Pessimistic   │
│ Optimistic    │
└───────────────┘

또는

┌───────────────┐
│ Redis Lock    │
│               │
│ Distributed   │
│ Lock          │
└───────────────┘
```

네 프로젝트에서는:

```
common/lock
        ↓
동시성 제어
```

와 연결해서 보면 된다.

특히 **재고 / 쿠폰 발급 / 잔액** 같은 부분에서 중요하다.

---

### 5. 장애 전파

```
"장애 전파"
        ↓
서비스 A가 서비스 B를
동기 HTTP로 호출
        ↓
Order Service
        ↓
Product Service
        ↓
Product DB 장애
        ↓
Product Service 응답 지연
        ↓
Order Service가 계속 기다림
        ↓
Order Thread Pool 고갈
        ↓
DB Connection Pool 고갈
        ↓
Order Service까지 장애
        ↓
다른 서비스까지 연쇄적으로 장애
```

해결 방법:

```
장애 전파
    ↓
Timeout
    ↓
일정 시간 이상 응답 없으면 포기
```

```
Timeout
    ↓
Retry
    ↓
실패하면 일정 횟수까지만 재시도
```

```
계속 장애 발생
    ↓
Circuit Breaker
    ↓
문제 서비스 호출을 일시적으로 차단
    ↓
장애가 다른 서비스로 퍼지는 것을 방지
```

# 전체를 한 번에 외우면

```
"분산 트랜잭션"
        ↓
여러 서비스의 DB를 하나의 트랜잭션으로
처리하기 어려움
        ↓
Saga / 보상 트랜잭션


"이벤트 유실"
        ↓
DB 저장은 성공했는데 Kafka 발행 실패
        ↓
Outbox
        ↓
DB에 이벤트를 저장해두고 Kafka로 재전송


"중복 이벤트"
        ↓
같은 Kafka 이벤트가 여러 번 처리될 수 있음
        ↓
Idempotency
        ↓
eventId로 이미 처리한 이벤트인지 확인


"동시성"
        ↓
여러 요청이 동시에 같은 데이터 변경
        ↓
Race Condition
        ↓
DB Lock / Optimistic Lock / Redis Distributed Lock


"장애 전파"
        ↓
A → B → C 서비스가 서로 동기 호출
        ↓
C 장애가 B → A로 전파
        ↓
Timeout / Retry / Circuit Breaker
```

그리고 **이 5개를 네 프로젝트의 구성요소와 연결하면**:

```
                 e-commerce MSA
                       │
       ┌───────────────┼────────────────┐
       │               │                │
       ▼               ▼                ▼
 분산 트랜잭션       이벤트 유실        중복 이벤트
       │               │                │
       ▼               ▼                ▼
 Saga/보상          common/outbox      Idempotency
 트랜잭션
       │               │                │
       │               ▼                │
       │             Kafka ◀────────────┘
       │               │
       │               ▼
       │          Payment Service
       │
       ├──────────────────────┐
       ▼                      ▼
    동시성                   장애 전파
       │                      │
       ▼                      ▼
 common/lock          Timeout/Retry/
 DB Lock              Circuit Breaker
```
