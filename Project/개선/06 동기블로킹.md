
```
클라이언트 → POST /api/v1/email/send
                    ↓
             DB에 인증번호 저장
                    ↓
         AWS SES API 호출 (네트워크 I/O)
                    ↓  ← 여기서 스레드가 멈춰서 기다림 (보통 100~300ms)
         SES 응답 수신 완료
                    ↓
             200 OK 응답 반환
```

톰캣은 기본적으로 스레드풀(기본 200개)로 요청을 처리하는데, 응답을 기다리는 동안 해당 스레드는 아무것도 못 하고 점유한다.

### 두 가지 자원이 동시에 묶인다

**1. 톰캣 스레드**
톰캣은 스레드풀(기본 200개)로 요청을 처리한다. `sendEmail()`은 외부 네트워크 I/O라서 SES가 응답할 때까지 해당 스레드는 아무것도 못 하고 점유된 채 대기한다. SES 응답 시간은 보통 100~300ms 수준이다.

**2. DB 커넥션**
`@Transactional`이 붙어 있으면 메서드가 끝날 때까지 DB 커넥션을 잡고 있는다. 즉 SES 응답을 기다리는 100~300ms 동안 DB 커넥션도 함께 점유된다. HikariCP 기본 커넥션풀은 10개다. 스레드 200개보다 커넥션 10개가 훨씬 빨리 고갈된다.

```
스레드 점유 시간  : DB 저장(~5ms) + SES 대기(~200ms) + 트랜잭션 커밋(~5ms)
커넥션 점유 시간  : 위와 동일 (트랜잭션 종료까지)

→ SES 대기 200ms 동안 스레드 + 커넥션 둘 다 묶임
````

## 해결 방법
### 방법 1. `@Async` (Spring 비동기) 

```
클라이언트 → POST /api/v1/email/send
                    ↓
             DB에 인증번호 저장
                    ↓
         비동기 스레드에 이메일 발송 위임
                    ↓
         200 OK 즉시 응답  ← HTTP 스레드는 여기서 해방
         
         (별도 스레드) AWS SES API 호출 → 완료
```

**장점**: 구현 간단, 추가 인프라 없음
**주의할 점**: `@Async`는 **같은 클래스 내에서 호출하면 동작 안 함** (프록시 기반이라 자기 자신 호출 시 프록시를 거치지 않음) → 별도 `EmailSender` 컴포넌트로 분리 필요

또한 `sendVerificationCode()`의 `@Transactional`과 `@Async`를 같이 쓰면 트랜잭션 커밋 전에 이메일이 발송될 수 있어서 이것도 분리해야 함

### 방법 2. 메시지 큐 (Kafka / RabbitMQ)

```
클라이언트 → POST /api/v1/email/send
                    ↓
             DB에 인증번호 저장
                    ↓
         메시지 큐에 이벤트 발행 (수 ms)
                    ↓
         200 OK 즉시 응답
         
         (별도 Consumer 서버) 큐에서 이벤트 소비 → SES 호출
```

**장점**: 발송 실패 시 재시도가 자연스럽고, 서버가 죽어도 메시지가 유실되지 않음. 대용량 트래픽에 강함
**단점**: Kafka/RabbitMQ 인프라 구축 필요, 복잡도 상승

### 방법 3. Spring WebFlux (리액티브)

톰캣 대신 Netty 기반으로 Non-blocking I/O 자체를 사용. 스레드 자체를 블로킹하지 않는 방식인데, 기존 코드가 MVC라면 전면 재작성이 필요해서 현실적으로는 마이그레이션 비용이 큼.

``` java
public class AsyncConfig implements AsyncConfigurer {  
    @Bean(name = "emailTaskExecutor")  
    public Executor emailTaskExecutor() { //이메일 설정  
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();  
        executor.setCorePoolSize(5);// 스레드 5개  
        executor.setMaxPoolSize(10);// 최대 10개까지  
        executor.setQueueCapacity(100); // 10개 다 바쁘면 100개까지 대기  
        executor.setThreadNamePrefix("email-async-");  
        executor.initialize();  
        return executor;  
    }  
```
