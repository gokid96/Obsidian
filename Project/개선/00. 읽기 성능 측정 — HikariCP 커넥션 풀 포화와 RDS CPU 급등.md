## 1. 테스트 개요

K6로 최대 100 VUs 기준 6분간 램프업/다운 시나리오를 실행
시나리오는 주요 조회 API 2개 사용자 폴더 조회와 공개페이지 폴더 조회 순서로 구성
전체적으로 **HTTP 오류율 0%** 를 기록하며 임계값은 통과하였으나
내부 지표에서 병목을 확인

## 4. 정리

```
VU 증가 (0 → 100)
  └─► DB 쿼리 급증
        └─► HikariCP Pool(10) 포화
              ├─► Pending 연결 23개 대기
              ├─► RDS CPU 53% 급등 (쿼리 처리 지연)
              └─► Connection Acquire Time 80ms 추가
                    └─► API 응답시간 500ms 초과
                          └─► Load Average 9.23 (CPU 큐 포화)
```

DB 쿼리가 병목의 근본 원인으로 보이므로
다음 단계에서 Hibernate SQL 로그로 실제 쿼리 수를 측정
