**1. 읽기 성능 측정**
- 쿼리 실행계획 (EXPLAIN / EXPLAIN ANALYZE)
- 슬로우 쿼리 로그
- APM 도구 (Pinpoint, Datadog, nGrinder)
- p50 / p95 / p99 응답시간 측정

**2. N+1 개선**
- N+1 문제가 뭔지 (1번 쿼리 후 N번 추가 쿼리)
- Fetch Join
- @EntityGraph
- Batch Size 설정 (`@BatchSize`, `default_batch_fetch_size`)
- DTO 직접 조회

**3. 인덱스**
- 인덱스 구조 (B-Tree)
- 단일 인덱스 vs 복합 인덱스
- 카디널리티
- 인덱스를 타지 않는 경우 (함수, LIKE '%앞', 형변환)
- 커버링 인덱스 (10번과 연결)

**4. 동시성 (낙관적 락)**
- 낙관적 락 vs 비관적 락
- `@Version` 사용법
- 충돌 시 재시도 전략 (Retry)
- 분산 환경에서의 한계 → Redis 분산락으로 연결

**5. 벌크연산**
- `saveAll()` vs 직접 bulk insert 차이
- `@Modifying` + JPQL 벌크 업데이트
- 영속성 컨텍스트 초기화 (`clearAutomatically`)
- JDBC Batch Insert

**6. 이메일 @Async**
- 동기 처리의 문제점 (응답 지연)
- `@Async` + `@EnableAsync`
- ThreadPoolTaskExecutor 설정
- 실패 시 처리 (예외 핸들링, 재시도)
- 더 나아가면 → MQ (Kafka, RabbitMQ) 비동기 처리

**7. 캐시**
- 캐시 읽기/쓰기 전략 → Cache-Aside, Write-Through, Write-Back, Read-Through
- 캐시 구성 전략 → Multi-Level Cache
- Cache Stampede / Thundering Herd 방지
- TTL 전략
- 캐시 무효화 패턴

**8. 스케일아웃 멀티 서버**
- 스케일업 vs 스케일아웃
- 세션 불일치 문제 → Session Clustering or Redis Session
- 로컬 캐시 불일치 문제 → Redis로 공유 캐시 전환
- 로드밸런서 (L4/L7)
- Sticky Session vs 무상태(Stateless) 설계

**9. Redis 캐시**
- Redis 자료구조 (String, Hash, List, Set, ZSet)
- `@Cacheable` / `@CacheEvict` / `@CachePut`
- 직렬화 전략 (JSON vs JDK)
- Redis vs Memcached 차이
- Redis 싱글스레드 동작 원리
- Redis 분산락 (Redisson)

1 JVM 힙 튜닝 
2 Tomcat 스레드 튜닝 
3 DB 커넥션 풀 튜닝 (HikariCP) 스레드 늘렸을 때 DB 커넥션이 병목될 수 있음
4 읽기/쓰기 DB 분리 (Read Replica) RDS 붙이면 한 단계 더 고도화 가능

**10. 심화**
- **네임드 락** : DB 레벨 분산락, `GET_LOCK()` / `RELEASE_LOCK()`
- **커버링 인덱스** : SELECT 컬럼까지 인덱스에 포함시켜 테이블 접근 제거
- **정규화** : 중복 제거, 데이터 정합성 확보, 쓰기 성능 향상
- **비정규화** : 조회 성능을 위해 의도적으로 중복 허용, 읽기 최적화
