## 2. 커버링 인덱스

> 쿼리 실행에 필요한 모든 컬럼이 인덱스 안에 포함되어, 
> 실제 테이블을 읽지 않아도 되는 인덱스

일반/복합 인덱스는 어떤 행이 필요한지 찾아준다. 하지만 찾은 행마다 실제 데이터를 읽으러 테이블 페이지로 이동하는 찾는 과정이 남아있다. 풀스캔 보다 빠르지만 커버링 인덱스보단 느리다

```
인덱스: 
workspace_id | folder_id | PK(행 주소)
    1            NULL      → 페이지 3
    1            NULL      → 페이지 7

① 인덱스에서 조건에 맞는 행 주소 3,7 수집
② 주소마다 테이블 페이지로 이동해서 데이터 읽음  ← 랜덤 I/O
```

SELECT하는 컬럼을 인덱스 안에 다 넣으면 ②가 사라진다. 이를 커버링 인덱스라고 한다.

#### 단점
인덱스에 컬럼을 추가할수록 크기가 커진다. 인덱스는 조회 시 빠르게 찾기 위한 별도 자료구조라 **쓰기(INSERT, UPDATE, DELETE) 시마다 인덱스도 함께 갱신** 되므로 컬럼이 많을수록 갱신 비용이 늘어난다.

그래서 커버링 인덱스는 읽기가 쓰기보다 압도적으로 많은 쿼리에 선택적으로 적용 해야한다.
