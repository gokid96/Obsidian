## 1. 동시성 제어 

### 1.1 단일 환경 동시성 제어
- **DB 레벨**: 비관적 락, 낙관적 락, 원자적 업데이트, 유니크 제약조건, 큐 기반 순차 처리
- **Java 레벨**: synchronized, ReentrantLock, userId별 Lock, Atomic 클래스, Semaphore, 스레드 안전 자료구조

### 1.2 분산 환경 동시성 제어
- **Redis 분산락**: SET NX EX, Redisson
- **Redis 원자적 연산**: INCR/DECR (수량 제한), SET NX (중복 방지), Sorted Set (대기열)
- **다층 방어**: Kafka 큐 → Redis 분산락 → 서비스 로직 → DB 레벨

### 1.3 트랜잭션 / 격리수준
- **ACID**: 원자성, 일관성, 격리성, 지속성
- **격리수준 4단계**: Read Uncommitted → Read Committed → Repeatable Read → Serializable
- **RC vs RR 비교**: 성능 vs 일관성 트레이드오프

### 1.4 데드락
- **발생 조건**: 상호 배제, 점유 대기, 비선점, 순환 대기
- **예방**: 락 순서 통일 + 재시도 로직 (실무 필수 조합)

## 2. 스케일아웃 전략

### 2.1 DB 확장 ⭐ 깊게 공부
- **마스터-레플리카**: 쓰기는 마스터, 읽기는 레플리카로 분리. 복제 지연 주의.
- **샤딩**: 데이터를 여러 DB에 분산. 쓰기 부하 분산. 크로스 샤드 조인/트랜잭션이 어려움.
- **CQRS**: 읽기와 쓰기를 분리하는 패턴. 단순 CQRS(라우팅 분리)부터 이벤트 드리븐까지.

### 2.2 서버(애플리케이션) 확장 ⭐ 깊게 공부
- **로드밸런서** (Nginx, ALB): 요청을 여러 서버에 분산. 라운드로빈, 가중치, 최소 연결 등 분배 방식.
- **오토스케일링** (AWS Auto Scaling): 트래픽에 따라 서버 수를 자동 증감. CPU/메모리 기준 또는 커스텀 지표.
- **스테이트리스 설계**: 서버에 상태를 저장하지 않아서 아무 서버나 요청 처리 가능. 세션은 Redis에 저장.

### 2.3 캐시 레벨 ⭐ 깊게 공부
- **Redis / Memcached**: DB 앞에 캐시를 두어서 읽기 요청이 DB까지 안 가게 함.
    - 캐시 전략: Cache-Aside, Write-Through, Write-Behind
    - 캐시 문제: Cache Stampede, 캐시 무효화
- **CDN**: 정적 파일(이미지, JS, CSS)을 전 세계 엣지 서버에 분산.

### 2.4 메시지 큐 레벨 ⭐ 깊게 공부
- **Kafka**: 대규모 이벤트 스트리밍. 파티션 기반 순서 보장. 컨슈머 그룹으로 병렬 처리.
- **RabbitMQ**: 전통적 메시지 큐. 라우팅/재시도 잘 되어 있음. Kafka보다 단순한 구조.
- 역할: 순간 트래픽 흡수, 서비스 간 비동기 통신, 느린 작업 분리.

### 2.5 아키텍처 레벨 
- **MSA**: 서비스별로 독립 배포/확장. 특정 서비스만 트래픽 많으면 그것만 스케일아웃.
- **API Gateway**: 인증, 라우팅, 속도 제한을 앞단에서 처리. Spring Cloud Gateway, Kong 등.

## 공부 우선순위

```
1순위: 동시성 제어 (완료)
2순위: DB 확장 (마스터-레플리카, 샤딩, CQRS) ← 면접 직접 출제
3순위: 캐시 (Redis 활용, 캐시 전략)
4순위: 메시지 큐 (Kafka 동작 원리)
5순위: 서버 확장, 아키텍처 (개념 수준)
```
